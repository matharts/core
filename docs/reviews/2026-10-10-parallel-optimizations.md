# 并行优化与类型隔离复测（2026-10-10）

本轮并行修改四个生产文件，随后串行测量。**生成一整旬的批次平均耗时减少约 82.5%；六爻查询、替换、翻转分别减少约 39.4%、53.2%、66.3%。** 两处解码改为直接匹配，但本次未得到稳定提速证据，不能把它们算作已证实的性能收益。此前纳音修改引出的 13 类 JSON 连带回退，在编译期单类型隔离中均未复现。

## 改动与取舍

| 位置 | 修改 | 保持的契约 |
| --- | --- | --- |
| [GrowthPhase::visit_str](../../src/growth_phase.rs#L192) | 十二个机器代码直接匹配到对应身份 | 代码、错误列表、数字入口和中文协议 |
| [SixClash::visit_str](../../src/branch.rs#L938) | 六个机器代码直接匹配到对应身份 | 配对身份、顺序、错误语义及其余地支关系 |
| [Xun::members](../../src/xun.rs#L86) | 只算一次旬首索引，直接构造十个连续干支 | 无分配、六旬各十值的顺序和合法配对 |
| [Hexagram 单爻操作](../../src/hexagram.rs#L87) | 用六位结构码读、置、清或异或指定爻位，再恢复上下卦 | `const`、私有字段、下卦在前、阳位为 1、有界爻位和编码 |

旬首索引最大 50，十次构造最大索引 59；最后递增到 60 仍不溢出。六爻的位移最大 5，结果仍小于 64；分拆后两个三爻索引都在 `0..8`。这些是范围论证，实际结果还通过独立全集样本校验。

解码保留字面量匹配，是为了让代码名直接指向固定身份，避免实现依赖 `CODES` 与 `ALL` 的相同位置；没有引入额外查表结构。它增加显式分支，重复映射由独立样本验证。本轮测量不支持“字面量匹配对所有小枚举一定更快”，也不再沿用旧混合基准的两个百分比作为当前单类型结论。

公开 API、中文文本、机器协议、冻结样本、领域规则与错误语义均未改变。没有新增生产依赖、feature、缓存、堆分配或 unsafe；不要求尚在准备的真实上层项目接入。

## 已测到的核心收益

单位为 ns/op，每项取 44 个批次平均值的中位数。旬成员的“一次操作”是生成整个十成员数组；六爻操作的一次操作是处理一个爻位。

四个修改项都超过 10% 改善，且四个独立进程的中位数范围不重叠。三个未修改控制项变化在约 1.4% 内。所有 median、P95、进程中位数、校准轮数及原始样本见 [数据记录](2026-10-10-parallel-optimizations.json)。

## 基准方法与可复现输入

- 本机 Apple M4 Max，36 GB 内存，Darwin 25.6.0 arm64；Rust 1.99.0、LLVM 23.1.1，目标 `aarch64-apple-darwin`。
- 默认 Cargo bench 优化配置，`serde` 开启；已核查 RUSTFLAGS、编码 RUSTFLAGS 和 bench/release 优化及 LTO 环境覆盖均未设置。
- 19 个枚举合计 146 个合法身份；每个类型保留九项：均匀、首、末、近似非法字符串，均匀及近似非法 JSON，均匀、边界及最大 u64 编号。
- 核心目标单独编译七项。独立预检覆盖 60 个干支、六旬 60 个成员、64 卦身份，以及 384 查询、768 替换、384 翻转；每个核心进程记录 1720 个预检案例。
- 每次编译型隔离只保留一个类型的泛型实例化，严格检查 1 组／9 项；默认目标严格检查 19 组／171 项，不是运行时过滤。
- 每比较项按 ABBAABBA 顺序运行，前后各四个独立进程；每进程 11 个批次均值，校准至至少 5ms，再预热一批。输入与结果使用 `black_box`，样本准备、分配及预检不计时。
- 共 312 个计时进程、30,712 个批次平均样本；每比较项每版本 44 个样本。P95 是批次均值的 nearest-rank 百分位，不是单次调用尾延迟。
- 前后合法输出及记录的非法输入错误信息一致。默认基准还单独执行了 `--verify-only`，19 组、920 个预检案例，零计时样本。

输入清单包含 16 个生产源文件、Cargo/锁文件/工具链/mise 四项、七份冻结样本及三个新基准文件，共 30 项。按路径排序，逐项 SHA256，然后对 `相对路径 + NUL + 文件 SHA256 + 换行` 连接串做 SHA256：

### 运行当前基准

```sh
rtk proxy mise exec -- cargo bench --bench serde_decode --features serde --locked
rtk proxy mise exec -- cargo bench --bench core_operations --features serde --locked
```

单类型编译例：

```sh
rtk proxy mise exec -- cargo rustc --bench serde_decode --profile bench --features serde --locked --message-format=json -- --cfg serde_bench_isolated --cfg 'serde_bench_type="GrowthPhase"'
```

运行编译结果 JSON 中 `compiler-artifact` 的 `executable` 路径即可测量；附加 `--verify-only` 只执行预检。完整 59 次构建命令和执行文件路径见数据记录。

复现修改前版本时，在独立副本应用 [本轮反向补丁](../../benches/baselines/other-optimizations-before-2026-10-10.patch)，使用 `git apply --unidiff-zero`；再应用 [纳音反向补丁](../../benches/baselines/nayin-scan-before-2026-10-10.patch) 得到纳音扫描版本。不要在当前工作区回退已有修改。

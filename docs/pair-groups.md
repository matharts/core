## 公共接口

- `ALL`、`index()`、`TryFrom<u8>`：按上表枚举全部身份；严格拒绝越界，不实现 `CyclicRing` 或排序。
- `members()`：固定长度两成员数组，按对应 `Stem`／`Branch` 索引升序，无堆分配。
- `contains(value)`、`partner_of(value)`：查询本组成员及伙伴；非成员的伙伴返回 `None`。
- `FiveCombination::from_stem()`／`SixCombination::from_branch()`：单值唯一归属，不声称完整配对已出现。
- `from_stems([a,b])`／`from_branches([a,b])`：完整无序配对识别；交换输入身份相同，重复或混组返回 `None`。
- `Stem::five_combination()`／`Branch::six_combination()`：归属便利入口。
- `FiveCombination::element()`：原表固定五行；不判断成化。

所有领域查询可用于 const 上下文。移除原 `Stem::combination_stem()`、`combination_element()` 与 `Branch::six_combination_partner()`；替换方式见[迁移说明](migration.md)。`partner_of()` 的 `Option` 用于任意组上的成员检查，不能用未校验的输入强行取伙伴。

## 编码与验证契约

Serde 输出采用原生 `unit_variant`：类型名、variant index 与代码由当前声明决定。可读输入只接受精确代码字符串（如 `"JiaJi"`、`"YinHai"`）；拒绝数字、中文名、对象、数组。紧凑输入使用原生枚举标识，拒绝越界标识与非 unit payload。两类代码不互相接受，不承诺第三方格式字节兼容。

[pair-groups-v1.json](../tests/fixtures/pair-groups-v1.json) 独立冻结11个身份、成员顺序、五合五行和必要负例。[pair_groups.rs](../tests/pair_groups.rs) 验证：

- 五组、六组分别完整分割十干、十二支且每个成员恰好一次；逐组检查全部成员和非成员的归属、伙伴与包含查询。
- 100个有序干干输入只有10个完整排列成功；144个有序支支输入只有12个完整排列成功，其余全部拒绝。
- 两类型分别枚举全部256个严格索引；验证 const 调用与模块／根导出。
- 样本结构、数量、每一行及负例内容明确断言；编码和解码分别核验，覆盖 JSON `from_str`／`from_value`、紧凑数字／字符串／字节标识、越界和错误 payload；专用观察器检查类型名、索引与代码。
- [公共示例](../examples/ganzhi.rs) 运行新接口；本地检查包含格式、严格 Clippy、debug／release 的 Serde 开关、两组裸机构建及严格 rustdoc。

测试只证明当前契约，不以本地通过替代远端 CI、实际消费项目、古籍影印校勘或合化条件验证。

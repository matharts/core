# 读取与维护领域文档

先读取统一领域词表，再按任务查规则依据和架构决策记录（Architecture Decision Record，ADR）。本仓库采用 single-context：根目录 `CONTEXT.md` 是唯一词表，其他文档引用其中的术语。

## 阅读入口

根据任务读取以下文档：

- 探索领域代码前，读取[领域词表](../../CONTEXT.md)。
- 阅读 `docs/adr/` 中与任务相关的决策记录。
- 涉及模型准入、固定对应、流派映射或应用条件时，核对相应类型的 rustdoc、源码和独立测试；准入要求见[项目约定](../../AGENTS.md)。
- 其他入口按[项目约定](../../AGENTS.md)的任务表和 [README 文档入口](../../README.md#文档)选取。

文档或 ADR 尚不存在时，继续核实源码和任务要求。只有术语或决策已经形成，才通过 `domain-modeling` 补充相应记录。

## 文件布局

按内容职责选择保存位置：

| 位置 | 维护内容 |
| --- | --- |
| `CONTEXT.md` | 仓库统一领域词表 |
| `docs/adr/` | 按编号保存已经形成的决策 |
| 领域类型的 rustdoc 与 `tests/` | 当前结构、关系与编码契约及独立验收 |
| `AGENTS.md` | 项目职责、模块组织和验证要求 |
| `README.md` | 接入、公共接口变更、开发验证及文档导航 |

## 使用与冲突处理

在 Issue、方案、假设和测试中使用词表术语，避免词表排除的同义替换。遇到缺失概念时，先核实它是否属于当前领域，再通过 `domain-modeling` 补充词表。

方案与已有 ADR 冲突时，指出对应记录和重审理由。历史规划、审查报告和实现记录用于解释背景，不能替代当前源码、测试或本次实施要求。

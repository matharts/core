# 地支三合、三会完整关系组

日期：2026-10-04。当前接口采用全库无兼容契约，本轮验证见[清理记录](breaking-cleanup.md)。

## 准入范围与来源

本次只加入完整三支集合身份及固定五行对应。三合取申子辰、巳酉丑、寅午戌、亥卯未；本库三会限定为寅卯辰、巳午未、申酉戌、亥子丑的四方分组。古籍中的“三会”可能另指其他含义，不能仅按词面统一。

采用以下电子原文转录，核验的是成员及对应，不采用其中的命理或占断结论：

- [《三命通会》卷二《论支元三合》](https://zh.wikisource.org/zh-hans/三命通會/卷二#论支元三合)：核对四组三合及五行。转录有“已／巳”等异写，本库沿用明确的地支值 `Si`；四土的四支集合不属于本次三支模型。
- [《滴天髓阐微·方局》任氏注原文转录](https://shuyuan.zhiming.life/read/滴天髓阐微/11)：核对命理中的四方分组与三合分组；方与局的应用论述另属上层。
- [《六壬大全》四库全书本卷八《全局课》及相关注文](https://zh.wikisource.org/zh-hans/六壬大全_(四庫全書本)/卷08)：核对四组三合的润下、炎上、曲直、从革对应，并核对其四方三支的同类对应。
- [《六壬指南》卷一《大六壬心印赋》注](https://zh.wikisource.org/zh-hans/六壬指南/1)：交叉核对六壬地盘的四方成员。

这提供命理与六壬两个具体消费场景的对照，支持下表限定的固定语义；未完成刻本影印校勘，也不声称所有古籍对“三会”的称谓或应用条件一致。

| 固定身份 | 命理成员与五行 | 六壬成员与五行 | 本库采用 |
| --- | --- | --- | --- |
| 申子辰三合 | 申子辰、水 | 申子辰、润下水 | 同一完整集合、水 |
| 巳酉丑三合 | 巳酉丑、金 | 巳酉丑、从革金 | 同一完整集合、金 |

| 亥卯未三合 | 亥卯未、木 | 亥卯未、曲直木 | 同一完整集合、木 |

## 模型与接口

新增 `ThreeCombination` 与 `ThreeMeeting` 两个四值枚举，均归入地支领域文件 `branch.rs`，同时提供 crate 根导出。两个类型不能相互替代，即使其五行对应相同。

| 接口 | 契约 |
| --- | --- |
| `ALL` | 四个身份，采用下表固定工程顺序 |
| `index()`、`TryFrom<u8>` | 零基身份索引与严格构造，拒绝 `4..=255`；无回绕构造 |
| `members()` | 完整三支数组，按现有 `Branch` 索引升序；不是原文生旺墓顺序或输入顺序 |
| `element()` | 固定对应五行，不表示成员本气五行已改变或实际化局 |
| `contains(branch)` | 单支是否属于该固定集合 |
| `from_branch(branch)` | 返回该支在当前关系类型中的唯一所属组；各类型分别完整分割十二支 |
| `from_branches([a,b,c])` | 无序完整集合识别；接受所有六种排列，拒绝重复成员或混组 |
| `Branch::three_combination()` / `three_meeting()` | 归属查询的便利入口 |

不实现 `CyclicRing` 或 `Ord`，不添加关系强弱、半合、拱局、吉凶或合化条件。完整组接口替代并移除旧 `three_combination_partners()`；不提供旧四步、八步伙伴元组顺序。

| 类型 | 索引与代码 | `members()` | 固定五行 |
| --- | --- | --- | --- |
| `ThreeCombination` | 0 `ShenZiChen` | 子、辰、申 | 水 |
| | 1 `SiYouChou` | 丑、巳、酉 | 金 |
| | 2 `YinWuXu` | 寅、午、戌 | 火 |
| | 3 `HaiMaoWei` | 卯、未、亥 | 木 |
| `ThreeMeeting` | 0 `YinMaoChen` | 寅、卯、辰 | 木 |
| | 1 `SiWuWei` | 巳、午、未 | 火 |
| | 2 `ShenYouXu` | 申、酉、戌 | 金 |
| | 3 `HaiZiChou` | 子、丑、亥 | 水 |

特别注意冬方：身份代码沿用亥子丑称谓，但成员数组按已约定的索引返回子、丑、亥；数组排列不表示方向或历法起点。

## 编码与验收

Serde 为可选特性，两类实现在地支领域文件 `branch.rs` 内分别维护。输出由 `Serialize` 派生为原生 `unit_variant`，代码与 variant index 对应当前声明。可读输入仅接受代码字符串，拒绝旧 unit 对象和数字；紧凑格式接受格式提供的合法枚举标识。不存在旧版本兼容承诺。

独立 [branch-groups-v1.json](../tests/fixtures/branch-groups-v1.json) 定义八个身份、成员顺序、五行、索引与当前代码；[branch_groups.rs](../tests/branch_groups.rs) 按以下要求验收：

- 每类四组恰好覆盖十二支且无重复；逐支归属、成员次序及五行与手写表一致。
- 每类穷举全部 `12³ = 1728` 个有序三支输入：24 个完整排列被识别，其余 1704 个拒绝，包含所有重复输入。
- 两类各遍历全部 256 个严格索引输入，拒绝所有越界值。
- 输出及输入分别对照固定样本，检查当前名称、index、代码和模型，分别覆盖可读与紧凑模式及拒绝项。
- [公共示例](../examples/ganzhi.rs) 实际运行完整组查询；验证 Serde 开／关 × debug／release、裸机构建与严格文档。

Jev 对来源限定准入的初次判断为支持（0.98），接口判断低置信度后由 Codex 核对具体契约并实施独立全集测试。用户随后明确取消全库兼容；当前删除旧伙伴入口并统一编码输入模式，实际完成性判断及本轮验证见[清理记录](breaking-cleanup.md)。

三合、三会仅提供固定集合和对应五行；电子转录尚未完成刻本影印校勘。本次未发布。

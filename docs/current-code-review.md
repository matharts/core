## 1. 必须优先处理的正确性问题

### R1 · P1：缺少导入导致整个 crate 无法编译

位置：[branch.rs:10](../src/branch.rs#L10)，缺失的导入应位于文件开头。

`HiddenStems` 的字段和 `hidden_stems()` 使用 `Stem`，但模块没有导入该类型。原仓库执行 `cargo check --no-default-features --offline` 和 `cargo test --all-features --locked` 都失败，编译器报告 3 个 `E0425`、28 个 `E0433`。这是一个缺失导入造成的 31 条诊断，不是 31 个独立缺陷。

处理：补入 `use crate::stem::Stem;`，随后在原仓库重新执行功能矩阵，才能确认后续编译状态。`god.rs:2` 的未使用导入也需要清理，否则不能通过将警告视为错误的检查。

### R2 · P1：反序列化绕过六十甲子不变量

位置：[sexagenary.rs:12](../src/sexagenary.rs#L12)。

构造函数 `new` 校验干支阴阳一致，但结构体直接派生 `Deserialize`，字段的私有性不能约束派生代码。用 Serde 的 `MapDeserializer` 输入 `stem=Jia, branch=Chou`，得到 `Ok(SexagenaryCycle { stem: Jia, branch: Chou })`。随后：

```text
非法甲丑 -> index() = 55 -> from_index(55) = 己未
非法甲丑 -> leader_branch() = 丑
```

这破坏了合法值集合、索引往返和旬首语义，并会污染纳音等派生查询。普通构造函数返回 `Option` 本身没有问题，问题是另一条公开入口没有执行相同校验。

处理：通过受校验的中间表示实现反序列化，例如 `#[serde(try_from = "RawGanzhi")]`，或者自定义 `Deserialize`，让所有构造路径共享校验。改成私有索引表示也必须校验反序列化的索引范围。验收应穷举 120 个干支配对，验证 60 个接受、60 个拒绝，并检查每个合法值的索引往返。参考：[Serde 的 try_from 属性](https://serde.rs/container-attrs.html#try_from)。

### R3 · P1：周期步进在极端偏移下 panic 或静默算错

位置：[math/ring.rs:25](../src/math/ring.rs#L25)，传播至 `Stem`、`Branch`、`Growth`，以及调用干支步进的 `SexagenaryCycle::offset`。

当前先计算 `self.index() as i32 + delta`，再取模；该加法可能已溢出。临时审查环境的结果：

| 输入 | 数学预期 | debug | release |
| --- | --- | --- | --- |
| `Stem::Yi.offset(i32::MAX)` | 壬 | panic | 丙 |
| `Branch::Chou.offset(i32::MAX)` | 申 | panic | 辰 |
| `Growth::MuYu.offset(i32::MAX)` | 墓 | panic | 帝旺 |
| 乙丑 `.offset(i32::MAX)` | 壬申 | panic | 丙辰 |

预期用更宽整数计算 `(index + delta).rem_euclid(period)`，没有调用被测步进实现。处理应使用足够宽的中间类型或先约减位移。直接使用 `wrapping_add` 不能修正此问题：模 2³² 的回绕不等于模 10、12、60 的周期运算。验收要覆盖所有起点与 `i32::MIN/MAX` 及其附近值，并同时执行 debug/release。参考：[Rust 整数溢出规则](https://doc.rust-lang.org/reference/expressions/operator-expr.html#overflow)。

## 2. 公共 API 与领域设计问题

### R4 · P2：构造与循环操作没有分清，公共数学接口允许零模数

位置：[math/ring.rs:3](../src/math/ring.rs#L3)、[stem.rs:29](../src/stem.rs#L29)、[branch.rs:38](../src/branch.rs#L38)、[sexagenary.rs:74](../src/sexagenary.rs#L74)。

`Stem::from_index(10)` 返回甲，`Branch::from_index(12)` 返回子。这是当前确定的取模行为，不是随机错误；但接口没有提供严格的外部索引构造路径，调用者容易把非法输入当成已验证的数据。另一个公开函数 `forward_distance(0, 1, 0)` 会 panic，签名及函数文档没有表达非零约束；trait 的“模数必须大于 0”也只是一条注释。

建议把严格构造与循环偏移命名分开。数学辅助函数若保留公开，应采用 `NonZeroU8` 或明确的可失败构造；没有外部泛型使用需求时可收为私有。`CyclicRing` 实际只描述周期序列，没有定义数学环的加法和乘法，“群／环”的混用应消除。先修复数值与边界契约，再决定是否需要公共 trait。

### R5 · P2：基础值直接绑定一套规则，难以表达跨体系复用边界

位置：[growth.rs:53](../src/growth.rs#L53)、[branch.rs:85](../src/branch.rs#L85)、[branch.rs:179](../src/branch.rs#L179)、[stem.rs:80](../src/stem.rs#L80)。

`Stem::growth_phase_at` 把阳顺阴逆、戊己随丙丁起点直接作为天干固有方法；藏干的主中余次序及有向相刑表也无独立规则身份。`transformed_element()` 只接收一个干，却以“化合五行”命名结果，没有说明仅查询配对所对应的五行。这些 API 容易让消费方将某个固定表或规则误当成不依赖体系的属性或已经发生的结果。

这不是认定这些表全部错误，也不是要求把所有关系移出 Core。应逐项确定：基础值、共同的固定关系、具名的规则映射、上下文应用判断。共同关系可保留；需要特定规则定义的运算应放具名模块或外部规则库；合化等实际成立条件不得隐藏在无条件属性中。首轮只需明确规则和函数，不必引入大型策略框架。

`God` 的 100 个干干分类由阴阳和五行关系计算，输入与视角是显式的，不能仅因“通常为日主”就判定算法必须移出。仍需补充统一术语、定义来源及跨体系使用依据。

### R6 · P2：Rust 标识符和布局直接成为数据协议

位置：[stem.rs:11](../src/stem.rs#L11)、[primitive.rs:6](../src/primitive.rs#L6)、[sexagenary.rs:12](../src/sexagenary.rs#L12)，其他枚举同样直接派生 Serde。

当前没有显式稳定代码或协议说明，枚举 variant 和结构体字段布局直接参与序列化。改名称或把干支二字段改为单索引时，可能同时改变已有数据表示；即使新版本的编码与解码能往返，也不能证明旧数据兼容。尚未确认已有发布或外部持久化用户，不能声称兼容破坏已经发生。

应在改名、改表示前确认消费方和兼容策略，固定支持格式及样本，分别验证编码输出和旧数据读取。不要将 `repr(u8)` 当成 Serde 协议保证。公开模型是否改名应与外部编码解耦。

### R7 · P2：没有可运行的行为验收资产

仓库未发现 `tests/`、Rust `#[test]`、`proptest!` 或 `.github/workflows/`。`Cargo.toml` 声明 `proptest` 并不意味着已经有性质测试。原仓库本轮测试止于编译失败，不能记作“0 个测试通过”。

恢复编译后，应优先将 R2、R3 固化为回归用例，再建立独立属性表、关系表、固定编码样本及功能组合检查。传统表格的文献校核和机器不变量验证须分别记录；检查某张表内部自洽不能证明其符合采用的定义。

### R8 · 原缺陷裁定已撤回：三刑类别有不同命名

2026-10-04 纠偏：进一步核对《三命通会》卷二发现，同篇引《三车一览》对调无恩、恃势两名，并认可其说。因此原注释也有文献依据，不能判为唯一错误。现有注释保留寅巳申无恩、丑戌未恃势，并明确这是采用版本；匹配方向不变。[《三命通会》卷二](https://zh.wikisource.org/wiki/三命通會_(四庫全書本)/卷02)。以下为已撤回的原判断，仅供追溯。

位置：[branch.rs:186](../src/branch.rs#L186)、[branch.rs:190](../src/branch.rs#L190)。

源码把寅巳申标为“恃势”、丑戌未标为“无恩”。本轮读取的《三命通会·卷二·论三刑》转录将寅巳申列为无恩、丑戌未列为恃势。应核对采用版本并更正注释。此问题只指类别标签，不据此认定布尔匹配方向写错。来源：[《论三刑》原文转录](https://sajumania.com/ebook/to01-05/to01-05-02-26.htm)；本轮未校对古籍影印页。

## 3. 其他需要决定的 API 取舍

- 命名取舍：保留 `Primitive`、`God`、`Growth`、`SexagenaryCycle` 与 `CyclicRing`。此前改名建议已按用户要求撤回；名称不作为缺陷或修复项。
- `nayin()` 实际返回纳音五行，尚未提供三十种纳音身份。保留原名，通过文档说明返回语义；是否增加纳音类型由真实需求决定。
- `triangle_combination()` 明确返回另外两支，并非当前存在的“完整三合组”API。如果需要稳定组身份，应另定义完整成员集合和顺序，不能在不说明迁移的情况下改变旧返回值。
- `HiddenStems` 三个字段公开，可以表达与某地支无关、重复或中气缺失而余气存在的组合。如果它只是任意数据容器，需要明确；若要代表已校验的藏干结果，就应限制构造。当前不能仅凭字段公开判定已有调用出错。
- `Ord` 是索引总序，`Sub` 是有方向的循环距离；需要明确文档或改用显式方法，避免被当成强弱比较或普通差值。
- `std` feature 当前为空，`lib.rs` 无条件 `#![no_std]`。这不是已发现的兼容故障，但默认／无默认两组配置尚无行为差异，应说明其用途，避免虚设能力开关。

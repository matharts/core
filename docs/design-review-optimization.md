## 修改

| 问题 | 实施结果 |
| --- | --- |
| F1：旧枚举 Serde 索引随声明位置变化 | `Primitive`、`Element`、`ElementRelation`、`Stem`、`Branch`、`God`、`Growth`、`Xun`、`Nayin` 的 92 个变体改用显式 Serde 名称、数字索引和字符串代码。映射不依赖 Rust 声明位置或 discriminant。 |
| F1：旧类型缺少模型验收 | 补充全部 92 个变体的模型、合法解码和负例检查，以及 `SexagenaryCycle`、`HiddenStems` 的结构体名、字段顺序、模型类别和可选槽位检查；保留原有 JSON 单向兼容测试。 |
| F2：冻结样本变更不触发本地测试 | `hk.pkl` 的测试输入增加 `tests/fixtures/**`。格式化和 Clippy 继续按源码输入筛选，测试能在这两个依赖步骤跳过时正常执行。 |
| F3：纳音迁移说明过时 | 更新当前 `nayin` 模块、根导出、`nayin_identity()` 与 `nayin()` 的关系；将曾经合并模块的过程标为历史阶段，并统一 JSON 与 Serde 模型承诺。 |

生产序列化代码仍在各自领域文件内，没有恢复独立 `gua_serde.rs` 或引入共享生产宏。显式映射增加了代码行数，换取声明顺序与协议索引解耦；纳音的私有访问器在同一文件内分开组织，避免单个函数过长。

测试专用的 `VariantModel` 从爻卦测试移至 `tests/support/mod.rs`，供两组协议测试共用。它只观察实际序列化模型，不生成预期编码或参与生产实现。

旧枚举继续接受原派生实现支持的 unit 对象、字符串及格式提供的数字/字节 variant 标识；没有套用爻卦对可读输入的额外限制。旧结构体的序列输入和额外字段兼容行为、藏干容器的独立可选槽位也保持不变；干支解码仍经过合法配对校验。

## 关键复现与验收

1. **先证明新测试能发现旧缺陷。** 新增模型测试在未改生产实现时通过；将审查阶段的旧 `Stem` 副本仅交换 `Jia/Yi` 声明，新测试失败，明确报告实际 `("Stem", 1, "Jia")` 与预期 `("Stem", 0, "Jia")` 不同。
2. **再证明实现已解耦。** 换成修复后的 `Stem`，在隔离副本中做同样的声明交换，全部 8 个编码测试通过；原生产源码没有交换声明。
3. **保留解码兼容性。** 全部旧变体检查数字标识、字符串与借用字符串、字节与借用字节、unit 对象；拒绝越界索引、非 unit payload、未知代码及其他非法 JSON 输入。结构体额外检查既有序列/额外字段输入。
4. **验证样本单独变更的触发。** 三个冻结样本分别运行 `hk check --slow --plan --json <文件>`，`cargo-test` 均为 `included`。仅传入 `encoding-v1.json` 实际运行 `hk check --slow`，四组特性测试确实执行并通过。
5. **验证错误样本导致失败。** 隔离副本中将冻结 `Stem` 代码 `Jia` 改为 `BROKEN`，编码测试有 3 项按预期失败、退出码 `101`；原样本未修改。
6. **验证迁移示例。** 抽取迁移文档的两个 Rust 代码块，在引用当前生产源码的临时 crate 中编译运行，2 项通过，包含根导出与模块路径的纳音导入。

临时复现位置为 `/tmp/matharts-core-design-mutant-20261004/` 与 `/tmp/matharts-core-optimization-check-20261004/`。其中错误样本是故意构造的反例，不是交付文件或常规测试入口；上述结果不依赖将这些临时文件加入仓库。
